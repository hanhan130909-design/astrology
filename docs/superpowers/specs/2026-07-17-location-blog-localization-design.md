# LunaXStar 定位、博客入口与本命盘中文内容设计

## 目标

在不改变本命盘、相位表和专业数据表视觉样式的前提下，完成三项修复：

1. 当前时间星盘使用彼此一致的地点、经纬度和时区，不再出现“台北市 + GMT+7”组合。
2. `/blog` 的 445 篇文章都能从卡片进入详情页，并提供唯一、可索引的页面 `H1`。
3. 中文本命盘页面的阅读指南、相关链接、FAQ 和 FAQ JSON-LD 使用一致的中文内容。

## 非目标

- 不调整星盘轮盘、行星符号、宫位、相位表或黄道状态表样式。
- 不重写博客文章正文，也不改变现有分页数量和排序。
- 不在本轮完整翻译本命盘操作界面的其他七种语言。
- 不接入会保存用户位置的数据库或第三方 IP 定位服务。

## 1. 当前地点与时区

### 数据优先级

页面首次加载和“新建星盘”使用同一条初始化链路：

1. 浏览器 `navigator.geolocation` 成功时，使用精确经纬度。
2. 浏览器定位拒绝、不可用或超时时，请求站内 `/api/location`，读取 Vercel 提供的 IP 城市、经纬度和 IANA 时区。
3. 两者都不可用时，使用台北默认值：北纬 25°03′、东经 121°30′、`Asia/Taipei`、GMT+8。

IP 定位只作为近似回退，界面城市名称需标识为近似位置；浏览器定位成功时显示“当前位置”。任何失败都不能把一处地点的坐标与另一处地点的时区组合。

### 时区解析

新增服务端时区解析边界：

- 坐标通过 `tz-lookup` 转换为 IANA 时区名称。
- IANA 时区通过 `Intl.DateTimeFormat` 计算指定出生日期和时间的 UTC 偏移，兼容夏令时。
- `/api/location` 接受合法经纬度和日期参数，用于浏览器定位及手动城市搜索后的时区更新。
- 所有经纬度、日期和 Vercel 请求头都需要范围校验；无效输入返回明确的 400 或无位置结果。

手动城市搜索成功后必须使用同一解析接口更新时区，替换当前按经度除以 15 的近似算法。时区显示统一为 `GMT+08:00`、`GMT+05:30` 等格式，并支持实际存在的半小时与 45 分钟偏移。

### 失败处理

- 时区解析失败但浏览器定位成功时，暂用浏览器当前时区，同时保留真实坐标。
- IP 位置不可用时进入台北 GMT+8 最终回退。
- 星盘 API 失败沿用现有错误事件，不引入阻塞弹窗。

## 2. 博客索引

- Hero 标题从 `h2` 改为页面唯一的 `h1`。
- 每个 `article` 内使用一个覆盖完整卡片的 Next.js `Link`，目标为 `/blog/{slug}`。
- 所有文章统一显示本地化“阅读全文”操作，不再按 `destiny-` ID 区分，也不再显示 `Snippet`。
- 保留当前分类、日期、摘要、标签、作者、分页大小和布局。
- 链接应支持键盘聚焦，并提供可见焦点样式。

## 3. 本命盘中文指南

- `NatalSeoContent` 保持服务端组件，避免把长文本重新放入客户端 JavaScript。
- 标题、四层结构、阅读顺序、出生时间说明、相关工具和七个 FAQ 全部翻译为简体中文。
- `natalFaq.ts` 继续作为可见 FAQ 与 JSON-LD 的唯一数据源，确保问题和回答逐字一致。
- `/transits` 的中文链接名称继续使用“星象日历”。
- 根页面默认 `lang` 调整为 `zh-CN`；用户主动切换语言时，现有语言上下文继续更新浏览器 `lang`。

## 4. 测试与验收

### 自动测试

- 定位测试覆盖浏览器位置、Vercel IP 回退、台北最终回退、非法坐标、GMT+8、GMT+5:30 和夏令时日期。
- 博客边界测试确认 Hero 存在唯一 `H1`、每个摘要都有详情链接、源码中不再出现 `Snippet`。
- SEO 测试确认中文标题层级、七个中文 FAQ、可见内容与 JSON-LD 一致。
- 继续运行现有 `test:acquisition`、出生资料、八字数据测试和生产构建。

### 浏览器验收

- `/natal` 自动生成非空星盘，显示的城市、坐标和 GMT 偏移相互一致。
- 浏览器拒绝定位时仍能生成星盘，不出现台北 GMT+7。
- 手动搜索城市后时区随地点更新。
- `/blog` 第一页 20 张卡片均可打开对应详情，分页仍为 445 篇、23 页。
- 中文本命盘只存在一个 `H1`，七个 FAQ 可展开，手机端无横向溢出。

## 发布

实现完成后合并到 `main`，部署到 Vercel，并把 `lunaxstar.com` 指向新部署。生产环境需要再次验证 `/natal`、`/blog`、一个普通 SEO 文章详情和一个 destiny 文章详情。
